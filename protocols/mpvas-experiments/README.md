# mPVAS
Source code underlying the publication "[Privacy-Preserving Data Aggregation with Public Verifiability Against Internal Adversaries](https://www.usenix.org/conference/usenixsecurity24/presentation/palazzo)".
## Installation
Tested on and developed for Debian 12.

1. Install [GNU Make](https://www.gnu.org/software/make/):
   ```shell
   sudo apt install -y make
   ```
2. Run the installer script:
   ```shell
   make install
   ```

   The installer will do the following:
   1. Install required packages with `apt`. (System-wide.)
   2. Install [pyenv](https://github.com/pyenv/pyenv). (For the current user only.)
   3. Install the required version of Python. (Inside pyenv.)
   4. Compile and install the [PBC library](https://crypto.stanford.edu/pbc/). (System-wide.)
   5. Compile and install the [Charm Python library](https://github.com/JHUISI/charm). (Inside pyenv.)
   6. Compile and install a few additional Python libraries. (Inside pyenv.)

   For more details on the exact installation procedure, see the file `GNUmakefile`.

### Verifying your installation
To check that all dependencies have installed correctly, run
```shell
make test
```
If something is wrong, the tests stop immediately, display the error messages, and return a non-zero exit code.
You can immediately recognise error messages from terms such as `Traceback` and `AssertionError`.
If the exit code is zero, or if no such messages appear, the tests have passed and you installed the dependencies correctly.

### Uninstallation
To undo the steps done during `make install`, run
```shell
make uninstall
```

Please note the following caveats:
1. This will _completely_ uninstall pyenv, even if you previously installed it yourself.
2. This will _not_ uninstall any packages installed with `apt`, because doing so would be dangerous.
   The uninstall script shows a list of packages that have been installed during installation, from which you can pick and choose which packages you do not need yourself.


## Usage
To run the mPVAS experiment suite, run
```shell
make run
```
A few notes:
* Outputs are stored in the directories `out/data/` and `out/logs/`.
* **Performance:**
  * The experiments will take approximately 72 hours, depending on your machine.
  * The experiments measure computation performance. For the best results, do not use your computer for anything else while the experiments are running, and ensure no other people are using the computer either.
* **Pausing and resuming:**
  * Outputs are stored after each individual experiment.
  * You can stop the experiment suite by pressing <kbd>Ctrl + C</kbd> on your keyboard. If you later run `make run` again, it will resume after the last completed experiment.
  * Resuming the experiment suite works by counting the outputs in `out/data/`. This counting method is fragile: Do not manually run experiments without `make`, and do not manually change parameters in `src/testrun/run.sh`. Otherwise, resuming the test suite may result in skipped or duplicated experiments.
  * Running `make test` does not write to `out/` and therefore does not affect the experiment counter. You can safely run `make test` at any point.
* **Completion:**
  * Once the suite is complete, the message "Completed all 720 experiments." is displayed.
  * If an experiment somehow unexpectedly fails, the suite will terminate immediately and show the relevant errors.
    You can immediately recognise error messages from terms such as `Traceback` and `AssertionError`.

Afterwards, to create plots of the results in `out/fig/`, run
```shell
make plot
```

### Inspecting published results
If you want to inspect the outputs generated by the authors for the paper without running the experiments yourself, you can download the pre-generated results from [4TU.ResearchData](https://doi.org/10.4121/56552cc8-7ebf-46ce-a6e0-668dd6065eb2.v1).
Download the file `mpvas-experiments.out.zip` and extract it so that the directory `out/` is in the same directory as this `README.md` file.
The directory `out/` should itself contain the directory `data/`, which contains the `.csv` files describing the experiments' outputs.
You can then either inspect those `.csv` files manually, or you can run
```shell
make plot
```
to generate the plots seen in the paper.

### Resetting
To **irreversibly** delete all outputs (data, logs, and figures), run
```shell
make clean  # WARNING: Deleting outputs is irreversible
```
After doing so, all experimental data you have gathered is irreversibly lost.
If you now run `make run`, the experiment suite will run from scratch.


## Development
This section applies only if you want to contribute to the source code of the mPVAS experiment suite.

To install the development dependencies, follow the installation procedures above, and then run
```shell
make install/contrib
```

You now have access to the following additional commands:
```shell
make test  # Runs a small suite of smoke tests. Does not write to output files
make black  # Formats all Python code
make mypy  # Runs the type checker
```

## Local Compatibility Notes
A previous Codex pass added a pure-Python compatibility shim so the source tree could run without real Charm/PBC.
That shim has now been preserved as:

```shell
src/charm_compat_backup/
```

The active recommended runtime is the real Charm/PBC path documented in `Real Pairing Notes` below.
The only local stub still active in the repo is `src/Cryptodome/`, which is acceptable for the current mPVAS source because the Ed25519 key path remains unused/commented out.
## Real Pairing Notes
The reproducibility package uses real Charm/PBC pairings rather than the local
algebra compatibility shim. Its portable build script installs PBC and Charm
under the package-local `.runtime/mpvas-real/` directory:

```shell
bash scripts/build_mpvas_real.sh
```

This packaged runner uses Python 3.10.x, matching the environment used for the
frozen real-pairing results. On hosts with a newer Python, use the package-root
Ubuntu 22.04 Dockerfile. The builder performs an mPVAS protocol-level self-test
after compilation instead of accepting a successful import alone.

No system-wide PBC/Charm installation or privileged install is required after
the standard Ubuntu/Debian development packages have been installed.

### Repo state for real mode
The old compatibility package was preserved as:

```shell
src/charm_compat_backup/
```

The active runtime no longer imports that folder. When using the package runner,
imports resolve to the bundled Charm source built against the bundled PBC
source.
The `src/Cryptodome/` stub is still present, but that is acceptable for the current mPVAS paper code because the Ed25519 key path in `ud/protocol.py` remains unused/commented out.

### Verified commands
From the reproducibility-package root, run a smoke test with the real pairing
implementation:

```shell
bash scripts/run_mpvas_verification.sh smoke
```

Run the standard verification-only comparison with:

```shell
bash scripts/run_verification_comparison.sh formal
```
